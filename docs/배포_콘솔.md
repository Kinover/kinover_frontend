# 배포 시 불필요한 로그(Console) 제거하기

로그가 많이 찍히면 앱 성능에 영향을 줄 수 있어서, 배포용 빌드에서는 `console.log`·`console.debug`·`console.info`가 자동으로 제거되게 설정했다.  
`error`와 `warn`은 남겨서 운영 중 예외 추적은 가능하게 두었다.

## 적용된 설정

- **Babel 플러그인**: `babel-plugin-transform-remove-console`
- **설정 위치**: `babel.config.js` → `env.production.plugins`
- **옵션**: `{ exclude: ['error', 'warn'] }` → `log`, `debug`, `info`만 제거

## 프로덕션 빌드 시 동작

- **Android**:  
  `npx react-native run-android --mode=release`  
  또는 Android Studio에서 Release 빌드 시 `NODE_ENV=production`으로 번들링되면서 위 플러그인이 적용된다.

- **iOS**:  
  `npx react-native run-ios --configuration Release`  
  Release 스킴으로 아카이브/빌드하면 프로덕션 번들에 동일하게 적용된다.

## 개발 시

`npx react-native start` 후 디버그 빌드(`run-android` / `run-ios` 기본값)에서는 **제거되지 않는다.**  
`env.production`은 Release 빌드에서만 사용된다.

## 제거되는 것 / 유지되는 것

| 제거됨 | 유지됨 |
|--------|--------|
| `console.log(...)` | `console.error(...)` |
| `console.debug(...)` | `console.warn(...)` |
| `console.info(...)` | |

## 수동으로 바꾸고 싶을 때

특정 메서드만 남기고 싶다면 `babel.config.js`의 `exclude` 배열을 수정하면 된다.

```js
['transform-remove-console', { exclude: ['error'] }]  // warn도 제거
```

전부 제거하려면:

```js
['transform-remove-console']
```

## 참고

- [Babel – babel-plugin-transform-remove-console](https://babeljs.io/docs/babel-plugin-transform-remove-console)
- React Native Release 빌드 시 Metro가 `NODE_ENV=production`으로 번들을 만들면 위 `env.production` 설정이 자동으로 적용된다.

## 보안 (API 에러 로깅)

API 에러를 로깅할 때 **`error.config` 전체나 `error.config.headers`는 절대 출력하지 말 것.**  
`Authorization` 같은 토큰이 들어갈 수 있다.  
필요하면 `error.config?.url`, `error.config?.method`, `error.response?.status`, `error.response?.data`만 쓰면 된다.
