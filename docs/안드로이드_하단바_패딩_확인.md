# 안드로이드 하단바 영역 확인

실기기에서 바텀시트 저장 버튼이 하단바에 가릴 때 확인할 항목 정리.

## 1. styles.xml – `windowTranslucentNavigation` 여부

**위치**: `android/app/src/main/res/values/styles.xml`

- **`android:windowTranslucentNavigation="true"`** 가 있으면  
  앱이 하단 네비게이션 바 영역까지 **투명하게** 그리기 때문에,  
  **반드시 JS에서 수동으로 하단 패딩**을 넉넉히 줘야 한다.
- 이 프로젝트에서는 **`false`로 명시**해 두었으므로,  
  **이 값을 바꾸지 말 것.** (바꾸면 하단 패딩을 더 넉넉히 줘야 함.)

```xml
<item name="android:windowTranslucentNavigation">false</item>
```

## 2. JS 쪽 패딩 강제

- **BottomSheetLayout.jsx**: Android일 때  
  `contentBottomPad` = `baseBottom` + `androidBottomPadding` + **ANDROID_FOOTER_BUFFER(16dp)**  
  로 넉넉히 줘서 Footer가 하단바에 가려지지 않게 되어 있다.
- **BottomSheetFooterButtons.jsx** / **MemoryDetailBottomSheet.jsx** (`CommentFooter`):  
  Android는 `layoutMetrics.getAndroidBottomSheetFooterInsetPx`로 **화면 추정 + 56dp fallback + 24dp 버퍼**를 통일 적용 (모달에서 `insets.bottom === 0`인 삼성 3버튼 내비 대비).
- **ScheduleEditorBottomSheet.jsx**:  
  `bottomSafe = Math.max(insets.bottom, 24)` 로 **최소 24dp** 확보.

## 참고

- `fitsSystemWindows="true"` 는 보통 **레이아웃 XML의 뷰**에 쓰는 속성이다.  
  React Native는 메인 뷰를 네이티브에서 만들기 때문에,  
  **테마에서 `windowTranslucentNavigation=false` 로 두고 + JS 패딩**으로 맞추는 방식이 맞다.
