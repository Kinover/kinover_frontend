# 인터넷이 끊겨도 당황하지 않는 앱 만들기

네트워크가 불안정한 곳에서 채팅이 먹통이 되는 문제를 해결하기 위해 NetInfo를 도입했다.  
연결이 끊기면 알림을 띄우고, 다시 연결되면 소켓을 자동으로 붙여 주는 흐름으로 맞춰 두었다.

## 동작

1. **오프라인 감지**  
   연결이 끊기면 `Alert`로 "연결 끊김" 메시지를 띄운다.
2. **재연결 감지**  
   다시 연결되면 "연결 복구" 메시지를 띄우고, 등록해 둔 재연결 콜백을 실행한다.
3. **재연결 콜백**  
   `registerReconnectCallback(cb)`로 콜백을 등록하면, 재연결 시 `cb()`가 호출된다.

## 재연결 시 해야 할 일

### 소켓 즉시 재연결

`App.jsx`의 `NetworkStatusBridge`에서 이미 등록해 두었다.

```js
import {reconnectIfNeeded} from 'features/chat/hooks/ChatSocket';

registerReconnectCallback(() => {
  reconnectIfNeeded();
});
```

### API 재요청 (필요 시)

특정 화면에서만 데이터를 다시 받고 싶다면, 해당 화면에서 콜백을 등록하면 된다.

```js
import {registerReconnectCallback} from 'hooks/useNetworkStatus';
import {fetchChatRoomListThunk} from 'features/chat/store/chatRoomThunk';

useEffect(() => {
  const unregister = registerReconnectCallback(() => {
    if (familyId != null && userId != null) {
      dispatch(fetchChatRoomListThunk(familyId, userId));
    }
  });
  return unregister;
}, [dispatch, familyId, userId]);
```

전역에서 한 번만 재요청하려면 `App.jsx`의 `NetworkStatusBridge` 안에서 `dispatch(fetchChatRoomListThunk(...))` 등을 호출하면 된다. 이때 `familyId`, `userId`는 `useSelector`로 가져오면 된다.

## 작업하면서 신경 쓴 점

단순히 알림만 띄우는 게 아니라, **다시 연결됐을 때 소켓을 자동으로 붙여 주는 것**이 핵심이었다.  
그래서 `registerReconnectCallback`에 `reconnectIfNeeded()`를 넣어 두고, NetInfo가 재연결을 감지하는 순간 채팅 소켓이 자동으로 재연결되도록 했다.  
알림만 있고 실제로 채팅이 안 되면 사용자가 더 당황할 수 있어서, 재연결 콜백에서 꼭 소켓까지 처리하도록 맞춰 두었다.

## 옵션

`useNetworkStatus(options)`:

- `alertWhenOffline`: 오프라인 시 알림 표시 (기본 `true`)
- `alertWhenReconnected`: 재연결 시 알림 표시 (기본 `true`)
