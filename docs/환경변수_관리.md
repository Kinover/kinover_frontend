# 환경 변수(.env) 셋팅 및 보안 관리

API 주소나 API 키 값을 코드에 직접 박아 두면 보안상 위험하고, 환경마다(개발/스테이징/운영) 바꿔 쓸 때마다 코드를 건드리게 된다.  
그래서 **react-native-config**로 `.env`를 쓰고, `src/config/constants.js`에서만 이 값들을 읽어 쓰도록 분리해 두었다.

---

## ⚠️ 이 파일은 깃허브에 올리면 절대 안 됨!

`.env`에는 실제 API URL, 카카오 키 같은 값이 들어간다.  
**반드시 `.gitignore`에 `.env`가 포함돼 있는지 확인하고, 실수로 커밋하지 말 것.** 팀원에게는 `.env.example`을 복사해서 쓰라고만 알려 주고, 본인만의 `.env`를 로컬에 두고 쓰면 된다.

---

## 셋팅 방법

1. **프로젝트 루트에 `.env` 파일 만들기**  
   `.env.example`을 복사한 뒤 값을 채운다.

   ```bash
   cp .env.example .env
   ```

2. **필수 변수 예시**

   ```env
   API_BASE_URL=https://kinover.shop/api
   WS_CHAT_BASE_URL=ws://kinover.shop:9090
   KAKAO_NATIVE_APP_KEY=your_kakao_native_app_key
   ```

3. **코드에서 쓰는 곳**  
   `src/config/constants.js`에서 위 변수들을 읽어 쓴다.  
   `.env`에 값이 없으면 해당 상수의 기본값(폴백)이 사용된다.

Android는 이미 `android/app/build.gradle`에서 `dotenv.gradle`을 적용한 상태라서, `.env`만 맞춰 두면 빌드 시 자동으로 읽힌다.

## 배포/환경별로 쓸 때

스테이징·프로덕션용으로 다른 값을 쓰려면:

- `ENVFILE=.env.production npx react-native run-android --mode=release` 처럼 `ENVFILE`로 파일을 지정할 수 있다.
- iOS는 빌드 스킴에서 `ENVFILE`을 설정하거나, 빌드 전에 사용할 `.env`를 복사해 두면 된다.

그래도 **민감한 API 키는 앱 번들에 그대로 들어가면 역공학으로 노출될 수 있다.**  
가능하면 서버 프록시를 두고, 클라이언트에는 꼭 필요한 최소한만 넣는 방식을 추천한다.
